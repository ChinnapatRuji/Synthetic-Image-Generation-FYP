    AI Synthetic Generation of Defect Images

    Synthetic defect image generation for AI-based manufacturing inspection when real defect images are scarce. LoRA models are trained with Kohya_ss and generate new defect images from real photos (image-to-image). An agentic loop, judged by a YOLO classifier trained on real TE images, tunes the hyperparameters so non-specialist users can produce reliable defect images.

    02

    Overview

    When a new product is rolled out, there are very few defect images to train the inspection model. Missed defects mean lower yield and dissatisfied customers, and the rarest defects are often the most critical.

    If realistic synthetic defect images can be generated from a small real dataset, inspection models can be trained from the start of a new product's life. This project turns the existing AITK tool into an agent-assisted workbench: industry users may not know how to tune hyperparameters, so an agent evaluates the generated images and recommends what to change. The agent recommends, the system executes, and a human approves, within budgets and with full logs.

    2.1Objectives

    1 · Model optimisation

    Improve on the UROP SDXL-LoRA model; now using Realistic Vision 5.1 with text-to-image and image-to-image generation.

    2 · Agent-assisted tuning

    Generated images are evaluated first; settings are tuned only if the images are not good enough, so users don't have to tune hyperparameters by hand.

    2a · Evaluator agent
    • A YOLO26n classifier, trained only on real TE images, checks every generated image.
    • An image passes if it is classified as its intended class with confidence ≥ 0.8.
    • The share of images that pass (pass rate) scores each run.
    See Section 08 →
    2b · Decision agent
    • Accept (pass rate ≥ 80%): save the settings and images. No tuning needed.
    • Borderline (50–80%): ask the Recommender for settings close to this run.
    • Reject (< 50%): ask the Recommender for different settings.
    2c · Recommender agent

    Proposes the next set of training hyperparameters, only when the verdict is Borderline or Reject.

    Details to be added by Shaun.

    3 · Reporting

    Per-run experiment report with a keep/reject recommendation, integrated into the AITK web app.

    Background & Prior Work

    A previous UROP team (CDE4301, AY2025/26 Sem 1) compared several generative approaches on TE Connectivity solder-pin welding images and built the AITK toolkit, a guided web app for training and generation. This project starts from their conclusions.

    3.1Literature review

    Diffusion models are the most widely used family for industrial defect synthesis. They learn to remove noise step by step, so generation can be steered by text, structural maps or a reference image.

    ApproachHow it worksReported result
    SD + ControlNet [1]Edge and depth maps from real PCBs guide generation, so defects follow the circuit layoutDetector accuracy 87.5% → 93.4%
    UniPCB [2]Fuses edge, depth and text cues at four resolution levels to keep PCB defects structurally plausible98.0% mAP@0.5
    DDPM for wafers [3]Generated wafer defects, screened by FIDYOLOv8 classification accuracy 98.7%

    Table 2. Diffusion-based defect synthesis in the literature.

    LoRA (Low-Rank Adaptation) is a fine-tuning technique, not a generative architecture. It keeps the base model frozen and trains only small low-rank matrices added to its layers [Hu et al., 2022]. We don't teach the model to draw from scratch; we nudge its existing visual knowledge toward one specific solder defect. This is why a LoRA can be trained from as few as ~10 real images per class.

    GAN-based

    StyleGAN3 for wafers [6], DT-GAN for defect transfer [7], wafer-dicing augmentation [8]. Trained from scratch, so they need more data.

    Transformers

    DALL·E builds images token by token [4]; Qwen-Image is a 20B diffusion transformer [5]. Strong prompt-following, but too heavy for local VRAM.

    Our choice

    Latent diffusion + LoRA: adapts from ~10 images per class, runs on one local GPU, and builds on the UROP baseline.

    We compared these families against our constraints: very few real images per defect class, and a toolkit that must run locally on a single GPU.

    3.2Model selection

    ApproachOutcomeVerdict
    VAE variants (β-VAE, perceptual + TV loss)Controllable but low-resolution and blurryRejected
    Qwen-Image / Qwen-Image-EditGood quality, but ~100 GB VRAM to trainNot viable locally
    Stable Diffusion 1.5 + LoRAArtifacts, outputs unrelated to defectsRejected
    Stable Diffusion 3.5 Medium + LoRABlurry, indistinct defectsRejected
    SDXL Base 1.0 + LoRAHighest fidelity; only model to improve downstream accuracyAdopted

    Table 3. Generative models evaluated in prior work.

    SDXL then went through two optimisation rounds. Natural-language prompts generated by a local Llama 7B model lowered FID but had mixed effects on accuracy. Training one LoRA per defect class ("individual") beat a single shared model on fidelity, FID and accuracy for clear-cut classes; for example, NG-No Solder accuracy rose from 73% to 93%. Individual training was adopted. The team wrapped the pipeline in the AITK web app: setup → training → generation → output.

    04

    Defect Taxonomy

    Defects are grouped by their physical failure mechanism, not just their visual appearance. Grounding generation in how a defect actually forms helps keep synthetic images physically plausible. Mechanisms are drawn from electronics-soldering literature [9–12] and will be confirmed against TE's process.

    OK: accepted weld

    Appearance: both pins present, even solder fillet, correct alignment.
    Mechanism: good wetting. Molten solder reacts with the electrode metal to form a thin, continuous intermetallic (IMC) layer, which gives an even fillet and a sound bond [9, 10].
    Real samples available: 30

    NG-Single

    Appearance: only one pin present in the joint.
    Mechanism: one electrode is not present at joining, likely a part-feeding or handling failure upstream. No specific literature found yet; to confirm with TE.
    Real samples available: 30

    NG-No Solder

    Appearance: bare pins, no solder deposit.
    Mechanism: non-wetting: solder does not bond to oxidised or contaminated surfaces, or when the flux is not active enough or the joint is not heated enough [11]. It can also occur if no solder is supplied.
    Real samples available: 25

    NG-Misaligned

    Appearance: pins offset or not parallel.
    Mechanism: a positional offset before joining. Placement studies show part position and solder position and volume drive shift; surface tension of molten solder can pull parts back into line (self-alignment), but small parts and large offsets are not fully corrected [12].
    Real samples available: 24

    5.2Prompts & captions

    Every caption and prompt follows the same pattern: trigger word + domain + class description. The trigger sldrjnt is kept first (keep_tokens = 1) so the LoRA ties it to this product. The domain is "close-up macro photo of a vertical metal electrode solder joint, dark blurry background".

    ClassDescription used in captions and prompts
    OKaligned vertically stacked electrodes, top and bottom electrode on the same vertical center axis, centered solder joint
    NG-Misalignmisaligned vertically stacked electrodes, top and bottom electrode on different vertical center axes, visible lateral offset at solder joint
    NG-Singlevertically stacked electrodes but only one electrode present, missing opposing electrode at the solder joint
    NG-No soldervertically stacked electrodes with no solder, missing solder material between top and bottom electrode

    Table 7. Class descriptions.

    Negative prompt

    horizontal alignment, side-by-side composition, two parallel lines, left and right objects, separate objects, duplicate, deformed, blurry background blobs, text, watermark

    Prompt variations

    Added to vary output: metallic texture and solder shape; lighting direction and exposure; solder appearance and highlights; camera position, magnification and depth of field; oxidation and discolouration.

    6.3Text-to-image vs image-to-image

    Txt2img starts from random noise, so the model must generate everything: electrode and solder geometry, alignment, camera composition, lighting and background. That gives high variety but many chances to be physically wrong, which matters for classes like NG-Misaligned where a small lateral shift separates OK from NG. Img2img starts from a real image and adds controlled noise, keeping camera angle and defect geometry while varying lighting, reflections and solder texture. Because the production camera setup is fixed, maximum diversity may not even be desirable.

    Txt2ImgImg2Img
    Starting pointRandom noiseReal manufacturing image
    Structural preservationLowHigh
    Image diversityHighModerate
    Camera consistencyMust be learnedInherited from reference

    Needs a reference imageNoYes
    Depends on raw image qualityNoYes

    6.4Results so far

    Txt2img: inconsistent

    Two images generated for NG-Misaligned came out one aligned, one misaligned. The model has not reliably learned the class-defining spatial relationship between the top and bottom electrodes, which may mean insufficient training or difficulty with precise geometry.

    Img2img: structurally consistent

    Good reference images gave realistic variations that kept electrode alignment, camera position and defect geometry. But quality depends on the reference: blur, artifacts or existing defects in a poor raw image are preserved or amplified.

    07

    Agentic Tuning Assistant

    The AITK toolkit lets users set training hyperparameters by hand or accept defaults, but good settings differ by defect class and are hard to judge without generative-AI experience. Industry search methods are also static: someone has to define the search space and iterations. AgentHPO (Agent-Driven Hyperparameter Optimisation) replaces this with three cooperating agents. Each new configuration is conditioned on the results of earlier runs.

    7.1Agents

    Evaluator

    Checks every generated image with a YOLO26n classifier trained only on real TE images. An image passes if YOLO predicts the intended class with confidence of 0.8 or more. The batch pass rate sets the verdict: Accept, Borderline or Reject (Section 08).

    Decision

    Acts on the verdict and the experiment history: Accept saves the config and images and ends the loop with no tuning, Borderline asks the Recommender to EXPLOIT (search near this run), Reject asks it to EXPLORE (search elsewhere). It can also TERMINATE when the budget is spent.

    Recommender

    Called only when the verdict is Borderline or Reject. Proposes the next LoRA training configuration with Bayesian optimisation (Optuna TPE), balancing exploration and exploitation. Uses dataset metadata, the search space, past trial results and Decision feedback. Needs no GPU and no LLM; it only picks the next experiment.

    The loop starts by generating images with the current settings (the defaults on the first run). The Evaluator scores them and the Decision agent gives a verdict. Settings are only re-tuned if the verdict is not Accept.

    Configuration ValidatorA deterministic validator sits between the Recommender and training. It rejects out-of-range or duplicate settings and enforces the run and GPU-hour budget.
    Design choice: no LLM requiredThe closed loop runs on numbers alone: YOLO judges, fixed rules decide, and Optuna TPE proposes new settings only when needed. An LLM could be added later to explain decisions, but nothing depends on one.

    7.5Two-stage evaluation

    Training a LoRA for many configurations is expensive, so tuning and downstream testing are separated.

    1. Stage 1, AgentHPO: about 15–20 trials search for strong image-generation configurations; the top few are retained.
    2. Stage 2, downstream validation: only the retained configurations go through the full inspection-model experiment.
    08

    Evaluation

    Generated images are judged on two questions: does each image show the intended defect? (a YOLO classifier trained on real TE images) and, later, do the images help? (a downstream inspection test, planned for Semester 2). This section covers the first question.

    8.1YOLO judge

    Ultralytics YOLO is widely used to detect and classify defective products in industry, with high reported accuracy on product images [Qi et al., 2024], including solder defects in automatic optical inspection [Dai et al., 2020].

    8.4Results: img2img vs txt2img

    Same YOLO judge, 50 generated images per class (200 per mode). Img2img keeps the real image's structure and passes 88% (176 of 200) → Accept. Txt2img has to invent the geometry and passes only 40% (80 of 200) → Reject, matching our visual inspection.

    Figure . YOLO pass rate per class. Each bar is labelled with its verdict: Accept ≥ 80%, Borderline 50–80%, Reject < 50%. Dashed lines mark the 50% and 80% thresholds.

    • Txt2img rarely produces a missing electrode: NG-Single electrode passes only 12%.
    • Img2img's weakest class is OK (70%): 15 of 50 "OK" images were read as defects.
    • Decision agent applied to these first runs: img2img → Accept; txt2img → Reject (explore new settings).
    CaveatA high pass rate does not prove the images are useful: img2img may stay too close to its reference images. Next: a near-duplicate check and the downstream test (M3).

    Planned work for Semester 2 (January to May 2027). See the Project Timeline (Section 10) for when each item happens.

    1 · UI/UX application

    Build the application that users work in: a guided, step-by-step flow from uploading images to approving generated results, usable without generative-AI expertise.

    2 · Complete the optimised generation model

    Finalise the generation model and its settings, building on the img2img results from Semester 1.

    3 · Evaluate uploaded datasets
